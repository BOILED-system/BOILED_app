# アプリ仕様書

BOILED活動管理アプリが「何ができるか」を説明する文書。コードが読めなくても、アプリで何が起きているかをこれ1本で把握できることを目指している。

> 技術的な中身(コードの構成)は [architecture.md](architecture.md)、サーバーやDBの話は [infrastructure.md](infrastructure.md)、日々の運用作業は [operations.md](operations.md) を参照。

---

## このアプリは何か

サークルの練習・イベント・出欠・集金をひとつのWebアプリで管理する。メンバーはスマホのブラウザから会員番号だけでログインし、自分に関係する練習の出欠登録や支払い報告ができる。幹部はメンバー管理・練習/イベント作成・集金の消込ができる。

- 本番URL: https://boiled-app.vercel.app
- アプリのインストールは不要(Webサイト)。アカウント作成も不要(幹部が会員登録すればログイン可能になる)

## ログインと権限

### ログイン

会員番号(例: `10001`)を入力するだけ。パスワードはない。

これは「お金の最終確認はPayPay・銀行振込の名義で担保できるので、アプリで厳密ななりすまし対策はしない」というサークル内の信頼関係に基づく意図的な設計。ログイン状態はブラウザ(localStorage)に保存され、ログアウトすると消える。

### 権限(admin / member)

各メンバーには登録時に `admin` か `member` のロールが設定される。違いは以下の通り。

| 操作 | member | admin |
|------|:---:|:---:|
| 練習・イベントの閲覧、出欠登録、支払い報告 | ✅ | ✅ |
| 出欠表の閲覧・CSV出力 | ✅ | ✅ |
| 精算(集金)の作成 | ✅ | ✅ |
| 練習・イベントの新規作成 | ❌ | ✅ |
| 練習・イベントの編集・削除 | 自分が作ったもののみ | すべて |
| メンバーの追加・一括登録・削除(プロフィール画面) | ❌ | ✅ |

つまり「見る・答える・報告する」は全員、「作る・消す・メンバーを管理する」は幹部(admin)、という緩やかな分担。バックエンドAPI側では権限チェックをしておらず、画面上の出し分けのみで運用している(これも信頼関係前提の設計)。

## 出欠登録の仕組み

出欠は練習1日程ごとに以下のいずれかを登録する。

| ステータス | 意味 |
|-----------|------|
| GO | 参加 |
| NO | 不参加 |
| LATE | 遅刻(メモに「2限後から」など理由を書く) |
| EARLY | 早退 |

練習一覧では「新歓Hiphop」のようなプロジェクト単位でカードがまとまっており、開くと全日程が展開されて一括で登録・変更できる。

**Discord通知**: イベント練(type がイベント練のもの)の当日に出欠を変更すると、該当ジャンルのDiscordチャンネルに自動通知が飛ぶ。「当日いきなり欠席に変えた」を幹部が見逃さないための仕組み。

## 練習の「対象者」の仕組み

練習を作るとき「誰に見せるか」を選べる。対象外のメンバーの画面には表示されない。

| 指定方式 | 説明 | 例 |
|---------|------|-----|
| ジャンル×期 | ジャンルと期(代)の組み合わせで絞る | 「Hiphopの17期・18期」 |
| ナンバー | ナンバー名簿に登録されたメンバー | 「M1のメンバー全員」 |
| 個別指定 | メンバーを1人ずつ選ぶ | 少人数の特別練 |
| +追加 | 上記の対象外でも強制的に含める | 「見学のOBも」 |
| −除外 | 対象に含まれていても外す | 「怪我で休養中の人」 |

このほか、プロジェクト単位で「コレオ(振付)メンバー」を登録でき、出欠表の先頭に表示される。

## 精算(集金)の仕組み

お金の流れは3ステップで、実際の送金はアプリの外(PayPay・銀行振込・現金)で行う。

```
unpaid(未払い) → reported(支払い報告済み) → confirmed(確認済み・消込完了)
      │                  │                        │
  メンバーが          メンバーが「PayPayで        会計が着金を確認して
  まだ何もして        払いました」と報告          「確認済み」に変更
  いない状態
```

精算の作成時には、練習と同じ方式で対象者を指定でき、金額・期限・支払い方法(銀行/PayPay/現金の集金担当者)を設定する。プロフィール画面には自分の未払いがアラート表示される。

## 外部サービスとの連携

### スプレッドシート同期(毎朝9時・自動)

スタジオ予定表のスプレッドシートに書かれた練習予定が、毎朝9時に自動でアプリとGoogleカレンダーに反映される。仕組みの詳細は [infrastructure.md](infrastructure.md) 参照。

重要なルール: **アプリ側で編集済みの練習は、シート同期で上書きしない**。食い違いが検出されるとDiscordに「シートとアプリで内容がズレています」という通知が飛び、人間がどちらが正かを判断する。

### Googleカレンダー連携

カレンダー画面から自分専用のカレンダーURLを取得してGoogleカレンダーに登録すると、自分が対象の練習・イベントが自動で表示され続ける(iCal購読方式)。反映は最大24時間遅れる(Googleカレンダー側の仕様)。

### LINE連携

LINEグループにボットを入れておくと、グループのメッセージをアプリで受信し、イベント詳細ページに「このイベントに関するLINEでの連絡」として紐付けられる。

### Discord通知

以下の2種類の通知が幹部向けDiscordチャンネルに飛ぶ。

1. **出欠変更通知**: イベント練当日の出欠変更(ジャンル別チャンネルに振り分け)
2. **シート同期の競合通知**: 毎朝の同期でアプリとシートの内容がズレていた場合

## データの中身(Firestore)

データはすべてGoogleのデータベース「Cloud Firestore」に保存されている。中身はFirebaseコンソール(Webの管理画面)から直接見られる。

| コレクション(≒表) | 中身 |
|------------------|------|
| `users` | メンバー。会員番号がID。名前・ふりがな・ロール(admin/member)・ジャンル・期 |
| `practiceSessions` | 練習1日程が1件。名前・日付・時間・場所・種別・対象者指定・コレオメンバー |
| `practiceSessions/{id}/rsvps` | その練習への出欠。メンバーごとにステータス(GO/NO/LATE/EARLY)とメモ |
| `events` | イベント。タイトル・日付・集合情報・タイムテーブル・画像URL |
| `numberRosters` | ナンバー名簿。名前とメンバーIDのリスト |
| `settlements` | 精算。タイトル・金額・期限・支払い方法・対象者 |
| `settlements/{id}/payments` | 支払い状況。メンバーごとに unpaid/reported/confirmed |
| `lineMessages` | LINEから受信したメッセージ |

イベント画像のファイル本体はFirestoreではなく「Firebase Storage」に保存される。

## 意図的に「やっていない」こと

後から見ると不思議に思える点は、だいたい意図的な設計判断。

- **パスワードなし・API認証なし**: 使いやすさ最優先。サークル内の信頼関係と、金銭の最終確認が外部サービスの名義で取れることが前提
- **管理画面の分離なし**: adminも同じ画面を使う(adminにだけボタンが多く表示される)
- **ネイティブアプリなし**: Webのみ。通知はDiscord/LINEという既存ツールに寄せている
- **リアルタイム同期なし**: シート同期は1日1回。即時性が必要なら手動同期(operations.md参照)
