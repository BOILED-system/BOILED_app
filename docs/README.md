# ドキュメントの歩き方

読む人のタイプ別に、どこから読めばいいかの案内。

## あなたはどのタイプ?

### 「アプリの使い方・運用を知りたい」(幹部・非エンジニア)

1. [spec.md](spec.md) — アプリに何ができるか、権限、データの意味
2. [operations.md](operations.md) — メンバー追加・集金・トラブル対処などの実務
3. [handover.md](handover.md) — **代替わり時は必読**。アカウント台帳とチェックリスト

コードやサーバーの話は読まなくていい。困ったらまず operations.md の「困ったときは」。

### 「システムを引き継ぐ・全体像を知りたい」(次期システム担当)

1. [spec.md](spec.md) — まずアプリとして何をするものかを把握
2. [infrastructure.md](infrastructure.md) — どのサービスで動いているか、設定値がどこにあるか
3. [handover.md](handover.md) — アカウントの引き継ぎ(**GASトリガーの罠**は必読)
4. [architecture.md](architecture.md) — コードの構成(変更するなら)

### 「コードを変更したい」(エンジニア)

1. ルートの [README.md](../README.md) — ローカル開発環境の立ち上げ(`make dev-setup`)
2. [architecture.md](architecture.md) — コード構成と「どこを触ればいいか」対応表
3. [spec.md](spec.md) — 仕様の確認

## このドキュメント群のルール

- **コードと食い違ったらコードが正**。気づいた人がドキュメントを直す
- 昔の設計資料(ハッカソン時代の要件定義・設計計画書)は2026年7月に削除した。必要なら `git log -- docs/` から掘り出せる
- ドキュメントは「未来の、事情を知らない人」に向けて書く。略語・内輪の呼び名には説明を付ける
