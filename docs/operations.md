## よくある作業

### メンバーを追加する

1. adminのアカウントでアプリにログイン
2. プロフィール画面(`/profile`)を開く
3. 「メンバー管理」から1人ずつ追加、またはCSV貼り付けで一括登録
   - CSV形式: `会員番号, 名前, 期(数字), ジャンル, ロール(admin/member), ふりがな`
4. 追加した会員番号を本人に伝えれば、その番号でログインできるようになる

新歓期など大量追加もこの画面のCSV一括登録でOK。**`scripts/` フォルダのスクリプトは使わないこと**(本番データを直接書き換える危険物)。

### 練習・イベントを作る

- 練習: `/practices` の作成フォーム(adminのみ表示)。対象者(ジャンル×期/ナンバー/個別)を指定
- イベント: `/events` の「+ イベントを追加」(adminのみ表示)
- 普段の練習は毎朝のシート同期で自動作成されるので、手で作るのは特別練など例外のみ

### 集金する(精算)

1. `/payments` で精算を作成(タイトル・金額・期限・対象者・支払い方法)
2. メンバーが送金 → アプリで「支払い報告」
3. 会計が口座・PayPayの着金を確認し、アプリで「確認済み」に変更(消込)

### シート同期を今すぐ実行したい

毎朝9時を待たずに反映したいとき:

1. スタジオ予定表スプレッドシートを開く
2. メニューバーの「同期」(独自メニュー)から手動実行

### バックエンドを手動デプロイする(要エンジニア・通常は不要)

通常は `main` にマージすればGCP側のトリガーが自動でデプロイする。自動デプロイが壊れたときだけ、gcloud CLIをセットアップ済みのPCで:

```bash
cd be
gcloud builds submit --tag gcr.io/boiled-app-bb43e/circle-api
gcloud run deploy circle-api \
  --image gcr.io/boiled-app-bb43e/circle-api \
  --region asia-northeast1 \
  --allow-unauthenticated
```

> ⚠️ デプロイ後、Cloud Runの環境変数([infrastructure.md](infrastructure.md)の台帳参照)が残っているか必ず確認すること。

フロントエンド(`fe/`)は `main` にマージすれば自動で本番反映される(数分)。

## 困ったときは(トラブルシューティング)

### 毎朝のシート同期が動いていない

原因の可能性が高い順に:

1. **GASのトリガーが消えた/オーナーが卒業した**
   → スプレッドシートの「拡張機能 > Apps Script > トリガー」を確認。なければ引き継いだ人のアカウントでエディタから `setupTrigger` 関数を一度実行して再設定
2. **合言葉の不一致**
   → GASのスクリプトプロパティ `APP_SYNC_TOKEN` と Cloud Run環境変数 `SHEET_SYNC_SECRET` が同じ値か確認
3. **Cloud Run側の障害**
   → GCPコンソール → Cloud Run → circle-api → ログ を確認

### Discord通知が来ない

1. Cloud Runの環境変数 `DISCORD_WEBHOOK_ALL`(とジャンル別の `DISCORD_WEBHOOK_〜`)が設定されているか確認
2. Discord側でWebhookが削除されていないか確認(サーバー設定 → 連携サービス → ウェブフック)
3. 消えていたらDiscordでWebhookを再作成し、そのURLをCloud Runの環境変数に設定し直す

※通知の失敗はどこにも記録されない仕組みなので、「いつから来ていないか」は特定できない。設定を直して次の通知を待つ。

### 画像がアップロードできない

CORS(セキュリティ設定)が原因のことが多い。ルート [README.md](../README.md#firebase-storageの設定) のCORS設定コマンドを実行する。本番ドメインを変えたときも同じ作業が必要。

### ログインできない(会員番号が見つからない)

その会員番号がメンバー登録されていない。adminがプロフィール画面で追加する。それでもダメならFirebaseコンソール → Firestore → `users` コレクションに該当の会員番号のドキュメントがあるか確認。

### 更新したはずのデータが古いまま見える

2種類のキャッシュがあり、どちらも時間で解消する:

- ブラウザ側: 最大15分(リロードやログインし直しでは消えない。別の操作で更新すると消えることがある)
- サーバー側: 最大30分

30分待っても直らない場合だけ異常を疑う。

### mainにマージしたのに本番に反映されない

- フロントエンド: Vercelのダッシュボードでデプロイが失敗していないか確認
- バックエンド: GCPコンソール → Cloud Build → 履歴 でビルドが失敗していないか確認。トリガー自体が消えている場合は Cloud Run → circle-api → 「継続的デプロイの設定」から再作成できる

### アプリ全体が落ちている(503など)

GCPコンソール → Cloud Run → circle-api → ログを確認。よくある原因は環境変数 `GCP_PROJECT_ID` の消失、Firestore接続失敗。リビジョンを1つ前に戻す(ロールバック)のもCloud Runコンソールからできる。
